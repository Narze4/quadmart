QuadMart password-reset recovery — October 29, 2026

The baseline browser test reproduced a real keyboard failure: Enter inside
the recovery email field attempted login form submission and sent no reset
request. Enter now submits recovery without needing the login password.
Recovery has an associated input label and alert. Login/reset submission
cannot overlap. A missing account gets the same confirmation as a successful
reset request, including when Firebase returns user-not-found explicitly.

Fourteen browser scenarios passed across Android-sized Chromium and iPhone-
sized WebKit, using only demo-quadmart emulators and synthetic addresses:
- Enter submits recovery; at most one request is in flight.
- Throttling and App Check denial retain the email and show useful guidance.
- Interrupted delivery preserves the email; explicit retry delivers locally.
- An invalid reset code leaves the original password working.
- A valid emulator code changes the test password; the old password fails,
  the replacement succeeds and the consumed reset code cannot be reused.
- A missing email receives identical generic confirmation.

Zero unexpected page errors; zero real emails sent. The development-only
diagnostic API also returned 404 in the emulator application.

The emulator reset completion uses the Firebase REST API, not Google's hosted
email action page. Hosted mailbox delivery/completion and new-password entry
remain owner steps. No real password, login account or email was changed.
Physical keyboards, cameras, cellular changes and phone OS suspension are
separate pending checks. Current-head full CI/deployment evidence is in PR 1.
