ACCESS SCENARIOS
- Uninvited verified Emory account cannot provision a marketplace profile,
  publish, read/query protected Firestore data, delete a listing or use photos.
- Membership and global policy writes are server-owned. Clients cannot approve
  themselves, list other memberships or change the admission policy.
- Approved synthetic seller/buyer complete listing, messaging, saving, sale
  and both reviews. Revocation prevents new messages/trades with that party.
- Verification, campus, suspension and closure remain enforced. Admission never
  overrides those checks; recent-auth closure remains available at the API.
- Malformed policy/membership denies access; provider failures return safe
  errors. The absent-policy development default remains explicitly separate
  from the required beta target configuration (see BETA-ACCESS-SETUP.txt).
- Browser approval/retry, live revocation, restored access, invalid policy,
  reload and switching accounts are exercised in Chromium and WebKit.

ISSUES FOUND AND CORRECTED
1. A permission-denied Firestore listener cannot recover without resubscribing.
   Code review found that restoring membership did not restart saved items if
   that listener had failed. It now resubscribes when admission changes.
   The regression visits Saved via
   in-app navigation after reapproval, without reloading or clicking Retry.
2. The new account-switch test navigated before asynchronous sign-out completed.
   It now waits for the app's own login redirect and enabled form first.
3. WebKit's cold-hydration test waited for the document load event after releasing
   JavaScript. It now waits for enabled inputs/submit within the same 30 seconds;
   pre-hydration disabled controls and actual successful login remain asserted.
4. WebKit can report cancelled loopback Firestore long polls during navigation.
   Only the existing exact diagnostic during a tracked navigation is counted
   separately. All other page errors, including outside navigation, still fail.
5. The new saved-item assertion initially looked for a heading, but the existing
   empty state is a paragraph. It now checks that exact visible text and records
   safe failure state; the application was not changed to satisfy the selector.
