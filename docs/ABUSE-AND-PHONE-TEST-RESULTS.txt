QuadMart development abuse and phone validation — October 29, 2026

Scope
- Isolated demo-quadmart Auth/Firestore emulators and production Next.js build.
- Two synthetic verified Emory accounts per browser: seller and buyer.
- Chromium with Pixel 7 settings and WebKit with iPhone 13 settings; both also exercised at 320 x 360 CSS pixels.
- This is browser/device emulation on the Mac, not physical iPhone/Android, camera, touch keyboard or cellular testing.

Implemented
- Firestore list queries require bounded limits and reject offsets; campus/member restrictions remain enforced.
- Atomic per-account and shared development attempt budgets for market API, uploads and protected photo requests. Rejection occurs before expensive upload/body/storage and photo lookup/download work.
- Photo 429 responses include Retry-After and preserve a manual retry control; message quota rejection preserves the draft.
- Scrollable small-screen menu, wrapped dashboard actions, smaller chat viewport, safe-area composer, long-text wrapping in chat/listings/report history/sale dialog, accessible listing inputs and decimal price keyboard hint.
- Login fields remain disabled until initial Auth state is ready, preventing pre-hydration input/click loss on cold or slow phone loads. The browser suite holds JavaScript responses to test this state before signing both accounts in.
- WebKit-specific Firestore long-polling fixed an observed dashboard loading stall. Other engines retain the SDK default. Upstream investigation: https://github.com/firebase/firebase-js-sdk/issues/9789 ; documented setting and performance tradeoff: https://firebase.google.com/docs/reference/js/firestore.firestoresettings .

Fixtures and limits
- Upload availability is enabled in the browser fixture so the oversized-file control can be exercised; no external storage is invoked by this test.
- HTTP quota rejection uses the real local routes. Successful image bytes in the retry UI are a generated JPEG intercepted by Playwright. This does not retest real camera uploads or Cloudinary delivery.
- Browser pages are exercised through app links. Hard reloads in Mac WebKit can emit cancelled localhost emulator-channel warnings; they were observed during diagnosis and are not an assertion bypass.

Development rollout
- Firestore rules compiled and deployed explicitly to quadmart-development.
- Only the private maintenance runtime's rules reference and matching manifest hash changed; all 24 pinned file hashes verified. Maintenance code and credentials remain unchanged.
- Vercel Hobby rule "Development API burst limit" is saved and enabled for the exact branch-preview host and /api/ prefix: 300 requests per IP per 60 seconds, action 429.
- External burst probes followed Vercel's sign-in redirect, so they did not validate edge rejection. A no-redirect probe confirmed HTTP 302 to vercel.com. Existing deployment access protection remains enabled. Treat edge enforcement as pending an authenticated test, and cover the chosen invitation hostname before launch.
- Production, main, billing and IAM were not changed.
